工作区就是你在 Amp 上的团队：成员、他们创建的线程、他们工作的[项目](/workspace)，以及一份共享账单。它也是"配置一次、全员生效"的地方——在工作区层级设置的插件、技能、agents、密钥、MCP 服务器和模型路由对所有成员生效。

没有工作区时就是单人使用：线程私有、积分归你、设置只影响你。一个用户最多属于一个工作区。

## 为什么建工作区

团队里不止一个人用 Amp 时就该建，你能得到：

- **共享线程** — 默认对工作区可见，可以读同事怎么解决问题、互相搜索线程、把线程当作 agent 的上下文。在线程里 `@` 同事可以拉进来[在同一个 orb 上结对](/collaborate/multiplayer)，同一工作区的 agent 也能[互相发消息](/orbs/agent-to-agent)
- **共享项目** — 工作区项目对每个成员可见，每个人的 orb 都会拿到项目的 setup 脚本和密钥
- **一份账单** — 工作区积分共享，管理员购买积分、管理付款方式与成员档位
- **一次配置** — 工作区的插件、技能、agents、密钥、MCP 服务器、模型供应商 key 对全员加载
- **策略** — 管理员决定线程能否分享到工作区之外、是否强制通行密钥；企业版还能禁止个人模型 key

## 创建工作区

打开工作区设置填写 **Create a Workspace**，选显示名和短名（短名成为 `ampcode.com/workspaces/<short-name>`）。已有线程时 Amp 会问是否共享给新工作区。你成为第一个管理员；有个人付费积分时可以选择转入工作区池。

要加入已有工作区，请成员邀请你：邀请会出现在同一页面和邮箱里。公司用 SSO 时，用工作邮箱登录会自动加入。

## 邀请成员

工作区设置的 **Members** 区域：管理员可以按邮箱邀请、创建带有效期与次数上限的邀请链接、修改角色，也可以允许普通成员发邮件邀请。

两种角色：

- **Member** — 使用工作区提供的一切，看共享线程与项目
- **Admin** — 再加上成员、账单、设置与策略管理；还能看到成员的私有线程

至少有一位成员处于有效 Megawatt/Gigawatt 档位的工作区可以配置 SAML/OIDC SSO；[企业版](/enterprise)不需要付费档位，还能使用更细的角色（Billing Manager、Auditor、Group Manager）并通过目录同步开通成员与分组。

## 个人 vs. 工作区

设置页顶部的 **Personal Settings** 与 **Workspace Settings** 切换两层。经验规则：

- 你**添加**的东西（插件、技能、agents、密钥、MCP 服务器、模型 key、域名）两层都存在并叠加：先用工作区的，再叠你自己的；同名时你的优先（远程 MCP 例外：同一 server ID 下项目 > 工作区 > 个人）
- 管理员设为**策略**的东西（分享、安全、成员可用范围）对所有人生效，覆盖个人设置
- 有**归属**的东西（线程、项目、积分）只有一个所有者：你或工作区

| 功能 | 个人 | 工作区 | 组合方式 |
| --- | --- | --- | --- |
| 线程 | 默认私有 | 默认共享给工作区 | 可自行改可见性；管理员设默认值并可禁止分享到工作区外 |
| 项目 | 只有你能看 | 成员都能用 | 创建时选所有者 |
| 积分 | 自己的余额 | 全员共享的一个池 | 团队工作区先用个人免费积分，再用工作区池 |
| 插件与技能 | 个人仓库 | 管理员管理的工作区仓库 | 都加载，同名时你的优先 |
| Agents | 自定义 agents | 工作区自定义 agents | 都可用，同名时你的优先 |
| Agent 指导 | 你的全局 AGENTS.md | 管理员管理的全局 AGENTS.md | 都作用于顶层 agent，仓库里的指导也生效 |
| 密钥与环境变量 | 只作用于你的 orb | 作用于每位成员的 orb | 个人 > 项目 > 工作区 |
| MCP 服务器 | 你连的 | 共享给全员 | 都可用；企业版可用 registry 限制 |
| 模型供应商 | 你的 key | 工作区 key 与路由规则 | 都用；企业版可禁止个人 key |
| Portal 域名 | 你的域名 | 工作区域名 + 默认 | 工作区默认域名作用于所有成员的 portal |
| Slack | 你安装并连自己的账号 | 管理员连工作区 Slack | 个人连接可先 @Amp，工作区限制仍生效 |
| 通行密钥 | 可为跨客户端访问要求 | 可对全员强制 | 工作区要求覆盖个人选择 |

## 工作区设置

管理员在工作区设置里管理：工作区名称与图标、共享余额、成员档位和高层策略（例如是否允许成员使用 orbs）。

## 分组

**Groups** 可以把成员分门别类，用于按组共享线程、按组做[配额](/enterprise/workspace-entitlements)与[模型授权](/enterprise/allowed-models)。

- **创建分组** — 在 Groups 里新建并命名，添加成员
- **管理成员** — 后续增删会自动反映到按组的共享与授权
- **按组共享线程** — 在分享对话框里选分组即可

## 服务账号

服务账号是没有个人登录的成员身份，适合自动化（例如 Slack 里的公共请求、CI 触发的线程）。管理员创建后，可把它用于 Slack 服务账号 Puck、自动化与订阅，费用同样计入工作区。

## 用量与账单

管理员可以查看成员用量、购买积分、管理付款方式、调整成员档位。

- **为成员付费** — 管理员可以把成员提升到付费档位，费用由工作区承担
- **积分** — 工作区积分共享，购买的积分 12 个月后过期
- **按成员配额** — 企业版可用[工作区配额](/enterprise/workspace-entitlements)限制每人花费

## 删除工作区

删除工作区会移除成员关系、共享项目与共享线程，并处理余额；个人线程与个人项目不受影响。操作前请确认账单与数据归属。

## 企业版

企业版额外提供：SCIM 目录同步、审计日志、IP 白名单、区域端点、线程保留策略、[MCP registry 白名单](/enterprise/mcp-registry-allowlist)、[线程可见性控制](/enterprise/thread-visibility)、[允许的模型](/enterprise/allowed-models)与[最小数据保留](/enterprise/minimal-data-retention)。
