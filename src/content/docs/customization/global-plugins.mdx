插件给 Amp 增加行为（工具、agent 模式），技能给 Amp 一类任务的说明与文件。Amp 把个人和工作区的插件、技能存在 Git 仓库里，称为"全局"，因为它们不绑定某个项目或某台机器，你在哪里用 Amp 就在哪里加载。

[Puck](/workspace/puck) 也会加载你的个人与工作区技能：它没有自己的 orb 或机器，所以能读技能说明和文件，但不能运行其中的脚本。插件只在有 orb、runner 或 CLI 的线程里运行，Puck 里不加载。

## 选范围

| 范围 | 给谁用 | 在哪生效 | 适合 |
| --- | --- | --- | --- |
| 个人 | 你 | 你用 Amp 的所有地方 | 分享前的试用 |
| 工作区 | 工作区所有人 | 成员使用 Amp 的所有地方 | 团队共享的稳定扩展 |

先做个人插件或技能，好用之后再分享，或请管理员发布给所有人。

## 找到别人分享的

直接问 Amp：

```text
我们团队有人分享了写发布说明的技能吗？
```

```text
有人做过 tmux 插件吗？
```

导入前 Amp 会给你看内容和来源。插件会在你的环境里跑代码，只导入你信任的。

## 导入给自己用

把分享链接粘进线程，说清楚放哪里：

```text
把这个共享插件导入我的个人插件：<shared-plugin-url>
```

```text
把 https://ampcode.com/@amp/plugins/oracle.ts 导入我的个人插件。
```

技能同理。Amp 会复制进你的个人仓库并记录来源以便以后更新；审阅改动后让它提交并推送，推送即发布。`amp plugins add @amp/oracle` 这类命令只装到当前机器；想在所有地方可用，用托管的个人导入。

## 自己写并测试

不必自己克隆仓库，直接在对话里描述：

```text
做一个个人插件，agent 每改一个文件就跑我们的格式化工具。
```

也可以把项目里的技能导入个人技能；要导入存在你电脑上的技能（如 `~/.agents/skills`），请在那台电脑的 CLI 线程里说（orb 线程与 Puck 读不到你电脑上的文件）。Amp 会打开对应仓库、改好、提交，推送前询问；推送后新线程自动加载，想在当前线程测试就让它重载。Puck 大约一分钟后拿到已发布的技能，已经打开的对话也会更新。

也可以自己在个人/工作区设置的 **Skills** 里点 **New Skill**，填名称、说明（何时使用）和指令；保存即发布。工作区技能只能由管理员修改。

## 分享给工作区

不想给所有人发布时：**Personal Settings → Plugins/Skills** → 选中条目 → **Share** → 开放给工作区 → 复制分享链接。把链接发给同事或粘进 Slack，他们可以查看、导入自己的副本，改动不会影响你的。

## 发布给所有人

工作区插件与技能对每个成员加载，由管理员管理。大改动先在个人范围测好，再让 Amp 复制进工作区仓库：

```text
把 Thorsten 的 plain-writing 插件复制到我们的工作区插件里。
```

Amp 会在工作区仓库准备一个可审阅的改动，推送前询问；推送即为工作区发布。新线程自动加载新版本，已存在的线程不会自动重载。

## 更新导入项

导入项不会不问就覆盖你的改动。让 Amp 检查是否有更新，然后审阅、提交、推送。也可以从仓库检出里更新单个条目：

```bash
amp plugins update <name>
amp skill update <name>
```

## 直接操作仓库

一般让 Amp 管理托管插件即可。需要直连 Git 时：

```bash
amp plugins repositories
amp skills repositories
amp clone user-plugins
amp clone user-skills
amp clone workspace-plugins
amp clone workspace-skills
```

每个仓库都是 Git 版本化的，提交并推送即发布。仓库所有者可以在高级设置里要求签名提交。

## 项目级与机器级替代

| 位置 | 何时用 |
| --- | --- |
| `.amp/plugins/` | 插件属于某个项目，随代码走 |
| `.agents/skills/` | 技能属于某个项目，随代码走 |
| `~/.config/amp/plugins/` | 只在这台机器运行 |
| `~/.config/agents/skills/` | 只在这台机器运行 |

`amp plugins add <url>` 默认装成机器级系统插件；它的 `--target workspace` 指当前项目的 `.amp/plugins/` 目录，不是托管的 Workspace Plugins 仓库。要发布托管的工作区插件，用 Amp 提示或上面的仓库流程。
