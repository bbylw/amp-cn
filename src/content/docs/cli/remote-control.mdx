跨客户端访问让你在 CLI 里启动的线程可以从 ampcode.com 继续：桌面或手机上打开那条线程发消息，随时接着干。

## 工作区设置

工作区管理员在成员设置里管理 **Cross-Client Access**。企业工作区（含自助企业版）或该设置已被关闭过时可见。默认开启，改名不影响已保存的值。

关闭后，成员不能从网页给 CLI 线程发消息，也不能在 CLI 之外于 runner 上新建线程：网页命令面板会隐藏 runner，`create_thread` 工具、Puck 和自动化也不能指向 runner。网页上打开 CLI 线程时，输入框位置会显示"你的工作区已禁用跨客户端访问"。自己的 orb 线程不受影响（它们的工具跑在沙箱里，而不是另一个客户端），仍可从网页和应用使用；其他成员的线程（包括其 orb 线程）保持只读。orb 由工作区 Orbs 设置里的 **Allow Users to Use Orbs** 和 **Orb Access Exceptions** 单独控制。

## 通行密钥认证

想在网页或应用里与 agent 交互时要求近期通行密钥认证，就在用户安全设置里打开 **Require Passkey Authentication for Web & App Interaction**；工作区管理员可以对所有成员强制。只有用自己 passkey 认证过的工作区管理员才能关掉这个要求。

开启期间，需要它的操作（例如应他人请求打开 multiplayer）无法从 Slack 等集成或推送通知上的按钮完成，需要到 Amp 里打开线程操作。

## 终端访问

网页终端提示终端访问被禁用时，用 `--remote-control-terminal` 重启 CLI：

```bash
amp --remote-control-terminal
```

然后刷新线程页面。`--no-remote-control-terminal` 显式关闭。两个参数都不给时，`AMP_REMOTE_CONTROL_TERMINAL=1` 开启、`=0` 关闭；显式参数优先。
