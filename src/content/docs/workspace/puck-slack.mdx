在频道或会话里 `@Amp`，就能不离开 Slack 提问、开始工作或管理已有线程。

## 安装

1. 在 Amp 设置里选 **Slack**，点 **Connect Slack**
2. 在 Slack 里查看权限、选择工作区并授权

属于 Amp 工作区的人也可以随时在个人集成里连自己的 Slack：这样就能 `@Amp`，你的线程也会获得以你的身份读取、搜索、发消息的 Slack 工具。不必等管理员先连工作区 Slack（但你的 Slack 工作区可能要求管理员批准安装应用）。Amp 工作区管理员可以在工作区集成里连 Slack，工作区的 Slack 限制仍然生效。

授权后 Amp 会显示 **Slack Connected**，把 `@Amp` 加进频道，然后在频道或会话里 @ 它即可开始。

## 能做什么

Puck 会把消息、会话和附带的图片当上下文。常见用法：

- **修用户报的 bug** — 用户带着截图报 bug，Amp 读图、复现、修好并回帖
- **处理线上事故** — 频道里出现告警，Amp 定位可疑提交、拉生产日志验证，并推送修复
- **闭环通知团队** — 让 Amp 告诉另一位同事问题已解决，顺手归档自己手上的线程
- **搜 Slack 找上下文** — Amp 可以检索与当前任务相关的讨论

## 会话与回复

第一次 @ 会为该 Slack 会话开一个 Puck 对话，Puck 在同一会话里回复，讨论和结果留在一起。任务较长时，Puck 先回一个执行线程的链接，然后保持安静，直到完成、被卡住或需要你时再回一条。运行期间 Slack 的工作指示器会显示当前步骤，等待你输入时会显示等待状态。想让 Puck 不再在该会话发言，直接跟它说，它会用表情回应而不是回复。

想再下一条指令就再 @ 一次。你在某会话里 @ 过之后，Puck 也会回应你后续的判断为"对它说"的回复；没有 @ 的回复不会新起 Puck，所以会话里还没有 Puck 的人必须先 @。想查看完整对话或继续，打开链接的 Amp 线程。

Amp 只能看到它所在的会话：在别人的私信或群私信里 @ 它，Slack 不会转达。请直接私信 Amp，或在它已加入的频道里 @。

每个人和自己的 Puck 对话，工作状态和回复署名会标明是谁的 Puck。个人 Puck 用该成员的权限和个人连接，所以同一会话里两个人可能得到不同结果。工作区管理员可以让 public 频道里的新请求以服务账号运行。

## 往 Slack 发消息

Amp 可以替你发送、编辑、删除消息和加表情，以你的身份或 `@Amp` 的身份。默认会先询问（你自己的私信和由 @Amp 开启的会话除外）：每次改动都先展示，批准后才执行，发送前还能改内容。想免询问，在 **Settings → Integrations & MCP** 的 Slack 卡上把 **Posting to Slack** 设为 **Allow**。

结构化答案可以发成 Slack 原生卡片（字段、表格、图表、回复按钮）；批准对话框会列出卡片上的全部内容，点回复按钮会以该成员的身份回复 Amp。

## Slack MCP

Puck 通过 Amp 内置的 Slack 工具（`slack_read`、`slack_write`）访问 Slack，这些**不是** Slack MCP 调用，用原生集成即可，不必配置 Slack 托管的 MCP 服务器。Slack 托管的 MCP 服务器是另一套配置，放在 MCP 设置里。

## 说明

在 Slack 的 AI agent 应用容器里使用 Amp 需要付费 Slack 方案；Slack 免费版仍可在频道与会话里 @Amp、收到线程回复并使用受支持的链接预览。Amp 使用大模型，可能产生不准确的回复、摘要、代码或结论，请审阅并测试后再依赖它或用于生产操作。Amp 不会用你的数据训练模型。
