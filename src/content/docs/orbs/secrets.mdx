orb 经常需要包仓库、云厂商、数据库和内部服务的凭据。你可以把值存在 Amp 设置里，也可以让 orb 用自己临时的 OIDC 身份。

服务支持 OIDC 时优先用它：orb 拿到的是范围很窄的临时凭据，不必在 Amp 里存长期密钥。需要固定令牌或密码的服务，用 Amp 的密钥。

## 密钥与环境变量

在下面任意一处添加值：

- **工作区设置** — 对该工作区所有 orb 生效，包括个人项目的 orb
- **项目设置** — 只对该项目的 orb 生效
- **个人设置** — 只对你自己的 orb 生效

同名时个人值覆盖项目值，项目值覆盖工作区值。

可以公开显示的内容（区域、功能开关）用环境变量；密码、API 令牌、私钥、带凭据的 URL 标成 secret，保存后 Amp 就不再显示它。

Amp 还会在 orb 的 shell 输出里遮掉密钥值的每一次出现。所以不要把很短的值或常见单词（比如 `file`、`true`）设成密钥，否则输出里这个词全都会被遮住——设置页会先警告。

环境变量允许空值（例如 `GIT_CONFIG_VALUE_0=` 用来重置 Git 配置），密钥必须有值。

也可以让 Amp 帮你管理，或在 CLI 用 `amp secrets`：

```bash
amp secrets --help
```

线程里 agent 用 `manage_amp` 工具的 `secrets` / `environment_variables` 主题。Amp 需要你已有的密钥时会弹私有输入框，值不会出现在线程里；它自己生成的随机值（比如 webhook 签名密钥）则直接存下。

## 值怎么进到 orb

orb 启动时，Amp 把值交给 agent 的执行器，并明文写进 `~/.env`；`~/.bashrc`、`~/.bash_profile`、`~/.profile` 都会读它，所以终端、登录 shell 和受管服务都能拿到。

`~/.env` 的权限是 0600，只有 orb 的 `user` 和 root 可读；agent 和你的命令都以 `user` 运行，因此能读到全部值。

Amp 在保存项目快照**之后**写 `~/.env`，并在取快照前删掉它，所以快照里不含这个文件。但你脚本自己写下的文件不受此保护：`.agents/setup` 能拿到工作区与项目的值，它写到磁盘的内容可能进入快照。orb 暂停时整个文件系统（含 `~/.env`）会被保存以便恢复。

想让运行中的 orb 刷新值，在它的终端里：

```bash
amp orb restart-processes
```

Amp 会等当前命令结束，然后重新加载值并重启执行器与受管服务。

## Orb 里的 Amp 凭据

orb 里的 `amp` CLI 用线程身份登录 Amp，这是会自动轮换的短期凭据。`amp threads`、`amp -x`、`amp orb id-token` 都不需要额外配置；Amp 托管仓库的 Git 操作使用只限 Git 的令牌。

账户级 `AMP_API_KEY` 正在从 orb 环境里移除。脚本如果直接读 `$AMP_API_KEY`，改成调用 `amp` CLI；确实要用访问令牌调 Amp API，就在安全设置里新建一个，存成别的名字（如 `MY_AMP_ACCESS_TOKEN`），再在脚本里导出为 `AMP_API_KEY`。`AMP_API_KEY` 本身是保留名，不能存成密钥。

## OIDC

### 怎么工作

orb 可以签发签名的 OpenID Connect ID 令牌。云厂商或私有服务验证令牌后，按"哪个工作区、项目、用户、线程拥有这个 orb"授予临时访问。

在 orb 里为某个服务签发令牌：

```bash
amp orb id-token --audience https://logs.example.com
```

命令只把令牌打到标准输出，方便命令替换和凭据助手。默认有效期 10 分钟，可请求 60 秒到 1 小时：

```bash
amp orb id-token --audience https://logs.example.com --ttl-seconds 3600
```

令牌用 RS256，公开端点：

- Issuer：`https://ampcode.com/api/workload-identity`
- Discovery：`https://ampcode.com/api/workload-identity/.well-known/openid-configuration`
- JWKS：`https://ampcode.com/api/workload-identity/jwks.json`

除标准的 `iss`、`aud`、`sub`、`iat`、`exp`、`jti` 外，还带这些声言：

| 声言 | 含义 |
| --- | --- |
| `workspace_id` | 所属工作区；个人线程没有 |
| `project_id` | 所属项目；无线程项目时没有 |
| `user_id` | 创建线程的用户；项目 setup 期间没有 |
| `thread_id` | 线程与 orb 身份；项目 setup 期间没有 |
| `email`、`email_verified` | 账号邮箱及验证状态；setup 期间没有 |
| `token_use` | `amp orb id-token` 打出的令牌为 `exchanged` |

默认 subject 范围是 `thread`：

```text
workspace:<workspace-id>:project:<project-id>:user:<user-id>:thread:<thread-id>
```

用 `--subject-scope user|project|workspace` 逐层放宽，`sub` 会相应变短。有些提供方只匹配标准 `sub`（例如 Entra ID 的联合凭据要求精确匹配），这时用 `--subject-scope workspace` 让同一工作区的所有 orb 产生相同的 `sub`。注意令牌就不再区分成员或线程，角色授权要收敛到最小资源集。

`project` 范围的 subject 会带上所有者，避免个人项目和同名项目冲突；项目换所有者时 subject 会变，需要同步更新接收方的配置。

项目预克隆、预 setup 与 `.agents/setup` 期间，请求凭据在 `/run/amp/workload-identity-request-token`，此时只能签发 project 或 workspace 范围（且 workspace 范围要求项目属于工作区），令牌里没有用户和线程声言。Amp 在保存快照前删掉该文件，恢复快照后在 `.agents/resume` 前写入新的请求凭据。

### 设计信任策略

每个信任 Amp 的服务用不同的 audience，并让两边配置完全一致，用能指明集成的 URL 或 URN。

audience 是标识符不是密码：任何 orb 都能请求同一个 audience，所以服务端还必须限制声言——工作区级访问匹配 `workspace_id`；单项目匹配 `workspace_id` + `project_id`；只允许特定用户时加 `user_id`；单个 orb 匹配 `thread_id`；提供方支持自定义条件时要求 `token_use == exchanged`。

访问规则用不可变的 ID 而不是 `email`。只暴露标准 OIDC 声言的提供方可以用 `sub`，它默认标识单个线程。

配置提供方之前先看令牌内容：

```bash
TOKEN="$(amp orb id-token --audience test-only)"
TOKEN="$TOKEN" python3 - <<'PY'
import base64, json, os
payload = os.environ['TOKEN'].split('.')[1]
payload += '=' * (-len(payload) % 4)
print(json.dumps(json.loads(base64.urlsafe_b64decode(payload)), indent=2))
PY
unset TOKEN
```

这只解码载荷，不做验证。任何服务在信任声言前都必须校验签名、issuer、audience 和有效期。

### MCP 服务器

`amp.mcpServers` 里的 HTTP MCP 服务器，只要某个 header 含 `${amp:id-token}`，就能收到为它自己源签发的 ID 令牌。本地 MCP 服务器需要别的服务的令牌时，可以自己运行 `amp orb id-token`。

### Google Cloud

用 Workload Identity Federation 把 Amp ID 令牌换成 Google 凭据。示例让一个 Amp 项目里的所有 orb 只读日志与指标，不需要服务账号密钥：

```bash
gcloud iam workload-identity-pools providers create-oidc "$PROVIDER_ID" \
  --project="$GCP_IDENTITY_PROJECT_ID" \
  --location=global \
  --workload-identity-pool="$POOL_ID" \
  --issuer-uri='https://ampcode.com/api/workload-identity' \
  --allowed-audiences="$AMP_GCP_AUDIENCE" \
  --attribute-mapping='google.subject=assertion.thread_id,attribute.workspace_id=assertion.workspace_id,attribute.project_id=assertion.project_id,attribute.user_id=assertion.user_id' \
  --attribute-condition="assertion.workspace_id == '${AMP_WORKSPACE_ID}' && assertion.project_id == '${AMP_PROJECT_ID}' && assertion.token_use == 'exchanged'"
```

`google.subject` 用 `thread_id`，因为它唯一且不超过 Google Cloud 的 127 字节限制。随后把最小角色授予 `principalSet://…/attribute.project_id/<amp-project-id>`。再写一个受控的凭据助手（调用 `amp orb id-token` 输出外部账号凭据 JSON），用 `gcloud iam workload-identity-pools create-cred-config` 生成外部账号文件，客户端库读 `GOOGLE_APPLICATION_CREDENTIALS` 即可。

### AWS

AWS 的 IAM OIDC 提供方可以让指定 orb 扮演角色，拿到临时凭据。AWS 会忽略 OIDC 自定义声言，所以信任策略只能用标准的 `aud` 和 `sub`：

```bash
aws iam create-open-id-connect-provider \
  --url 'https://ampcode.com/api/workload-identity' \
  --client-id-list "$AWS_OIDC_AUDIENCE"
```

一个账号对同一 issuer 只能有一个提供方，已存在时用 `add-client-id-to-open-id-connect-provider` 追加 audience。信任策略里条件键去掉 `https://` 前缀但保留路径：

```json
{
  "Effect": "Allow",
  "Principal": { "Federated": "arn:aws:iam::<account>:oidc-provider/ampcode.com/api/workload-identity" },
  "Action": "sts:AssumeRoleWithWebIdentity",
  "Condition": {
    "StringEquals": {
      "ampcode.com/api/workload-identity:aud": "urn:amp:aws:logs:<account>",
      "ampcode.com/api/workload-identity:sub": "workspace:<ws>:project:<project>"
    }
  }
}
```

orb 里把令牌写进权限 600 的临时文件，设好 `AWS_ROLE_ARN`、`AWS_ROLE_SESSION_NAME`、`AWS_WEB_IDENTITY_TOKEN_FILE` 后正常用 AWS CLI/SDK 即可。不要在签发令牌前后开 shell 跟踪；任务比令牌活得久时，在下一次凭据刷新前重新签发。
