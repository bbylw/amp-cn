Amp 的 agent 可以启动别的 agent、给它们下指令、交换文件，并把结果带回当前线程。要在不打断手头工作的情况下委派一件独立任务时用它。

## 示例

### 派一个支线任务

让 Amp 在 orb 里开新线程，自己继续干：

```text
用你了解的这个不相关 bug 开一个 orb 线程，让它修好并回报，然后你继续做当前任务。
```

新线程有自己的对话、上下文窗口、工作副本和 orb。它**不会**自动共享未提交的文件，所以要让 agent 把对方需要的文件或结论发过去。

### 并行展开互不相关的工作

几个 agent 可以同时调查一个问题的不同部分：

```text
并行开四个 low 模式的线程，在 Chrome 里用四种屏幕尺寸测这个流程。
让每个线程带着截图回报结果，然后在这里汇总四份结果。
```

轻量的并发展开用小规格 orb，构建或吃资源的测试用大规格，见[规格与计费](/orbs/sizes)。这种展开也是检验仓库对 agent 友好程度的好办法：不给任何提示地开几个新 orb，看每个能走多远。

### 交换文件

结果没法用消息表达清楚时，让 agent 传文件：

```text
在 docs 项目里开一个线程，把这里的 API schema 和截图发给它，
让它更新文档，并回报改了哪些文件。
```

线程各有独立工作区。消息本身不传文件或提交，只有你明确要求发送或取回时 Amp 才做显式传输。

### 继续早前的工作

agent 能找到旧线程，把有用的文件拉进当前工作区：

```text
找到我放弃的那个原型线程，把它有用的文件拿过来，和现在的做法合并。
```

### 跨项目或跨机器委派

对方可以跑在另一个 Amp 项目、一个 orb，或装了 Amp [runner](/cli/runners) 的机器上：

```text
在 docs 项目里启动一个 agent。把记录这次 API 变更所需的东西发给它，完成后回报。
```

```text
在 cloud-dev-box runner 上开一个线程，把这个测试矩阵发过去。
让它每一行跑十次并返回原始结果。
```

需要持续协调、或要改同一批文件的任务，留在当前线程做；结果明确、能独立推进的工作才交给另一个 agent。
