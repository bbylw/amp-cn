Amp 会代你运行工具和 shell 命令来检查代码、跑测试、快速迭代。**默认情况下，Amp 运行工具前不会请求批准。**

:::caution
Amp 会作用于工作区里的内容。不受信任的仓库、MCP 服务器和外部输入都可能影响它的行为。如果你经常处理不受信任的来源，考虑写自定义策略插件，或使用隔离的开发环境。
:::

## 内置工具

运行 `amp tools list` 查看当前版本的内置工具。

## 子 agent

Amp 通过 Task 工具把聚焦工作交给子 agent。你可以直接要求，例如「让子 agent 审查最后一次提交」「用子 agent 研究 Zod 如何实现可辨识联合」。详见 [模型与子 agent](/models/subagents)。

## Painter（图像生成与编辑）

Amp 可以用 Painter 工具生成和编辑图片，底层是 GPT Image 2.5 Sunburst。

- 可以在提示中用 `@` 提及最多 3 张参考图，说明每张要保留什么、可以改什么
- 每次调用生成一张图；Amp 可以在一次调用里要求多个变体，也可以多次调用
- 需要叠在现有内容上的独立素材（logo、sprite），要求**透明背景**。Amp 会把工具的 `background` 选项设为 `transparent`，只在提示里写「透明」并不可靠
- 完整构图（UI 样机、海报）以及自带设计背景的应用图标，应保持不透明背景
- 做 UI 创意时，Amp 更倾向于构建可交互原型而不是出图

## 权限

Amp 默认不询问工具批准。需要控制工具使用时，写[自定义插件](/customization/plugins)；工作区管理员可以把它作为全局工作区插件分发。
