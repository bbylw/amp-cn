🚀 介绍

Amp 是为前沿模型打造的编程代理与开发环境。它不再只是终端里的一个工具，而是一套贯穿网页、桌面、手机和 CLI 的工作方式。

🧠 多模型

GPT-5.6、Claude Fable 5.1、快速模型……Amp 会为每类工作挑最合适的模型

☁️ Orbs

Amp 为每个线程创建的机器，代码、工具和插件都已就绪。发出提示、合上笔记本，代理继续干活

📱 无处不在

在 iPhone 上发起，在 Mac 上查看，在 TUI 里继续。线程就绪时应用会通知你

🎯 固执己见

你始终用到 Amp 最好的部分。我们自己不用、不爱用的功能，会被砍掉

⚡ 站在前沿

模型走到哪，Amp 跟到哪。没有向后兼容，没有历史包袱

🧵 线程

与 Amp 的每次交互都可保存、跨设备继续、分享给同事

在哪儿用

  • 🌐
    网页 — 打开 ampcode.com，无需安装。发起线程后 Amp 会在 orb 中工作
  • 💻
    Mac / iPhone / iPad / Android / Windows / Linux — 原生应用提供听写、跨应用分享和通知
  • ⌨️
    终端 — CLI 可在你自己的机器、编辑器终端或脚本中运行 Amp
  • 🫧
    Puck — 帮你启动和协调代理的个人助理，见 Puck

📦 快速开始

三步开始

  1. 登录 — 打开 ampcode.com 注册并登录。Orb 跑在 Amp 云端，无需安装任何东西
  2. 添加代码 — 用 Git 仓库创建一个项目，或者以「No Project」开始
  3. 在 Orb 中运行代理 — 在新线程对话框里把执行位置设为 New Orb，选好项目，描述你想要的结果

💡 代理拥有一整台机器，所以可以直接安装依赖、启动应用、开浏览器做端到端验证。让它先证明改动可用，再交给你看。

安装 CLI

curl -fsSL https://ampcode.com/install.sh | bash

安装后运行 amp 进入交互模式。首次运行会提示登录。

也支持 Homebrew 与 npm（macOS / Linux / WSL；Windows 请使用 WSL）。

安装应用

平台 要求
macOS Apple 芯片，macOS 26 及以上
iPhone / iPad iOS / iPadOS 26 及以上（TestFlight 测试版）
Android Android 13 及以上（APK）
Windows Windows 10 1809+ 或 Windows 11
Linux apt / dnf / AUR，x86-64 或 ARM64

应用不需要额外安装任何东西，因为代理运行在 orb 里，而不是你的设备上。

🧠 模型选择器

用模型选择器决定线程跑在哪个模型上、用多大的思考强度。选择器还会显示每个模型由谁付费。

⚠️ 模式（Dial）已被模型选择器取代。旧的 low / medium / high / ultra 四种模式不再用于新线程。新线程默认从 Staff Pick 开始；已有线程保持原来的模型继续工作。

Staff Pick（官方推荐）

Staff Pick 是 Amp 团队为大多数工作会选择的模型，目前是 Claude Opus 5.5。团队会持续测试，当别的模型表现更好时就换掉它。如果你不想挑模型，保持 Staff Pick 即可。

你选模型，Amp 围绕它构建代理：每个模型都有自己的系统提示与工具集，换模型时两者都会变。

选择器中能调什么

  • Effort（思考强度） — 模型回答前推理多少。越高越慢、消耗 token 越多；越低越快越省。选择器只显示该模型支持的档位，并标出推荐档
  • Speed（速度） — 在 Standard、Fast 之间切换，部分模型还支持 Plaid。新线程默认 Standard
  • Other Models — 列出你可用的其它模型与代理

打开方式

  • 网页/应用：点击提示框下方的模型按钮
  • 网页或 CLI：按 Ctrl+S
  • CLI 中切换线程模型：Ctrl+S 选模型，用 ← → 调 effort。只有线程所有者能切换

切换是有成本的：提示缓存属于某个模型，新模型要无缓存地重读整个线程，切换后的第一条消息会比平时更贵。

新线程从哪儿开始

设置 行为
Staff Pick（默认） 每个新线程都用 Staff Pick；若你的 Top Models 里没有它，则用第一个 Top Model
Last Choice 用你上次选的模型
固定模型 所有新线程都用你指定的那个模型

在 Settings → Model Selector 中可以调整 Top Models（最多 8 个）、它们的建议 effort 与顺序。

用命令行指定模型

amp -x "Review this repository" --model openai/gpt-6-astra --effort xhigh

--model 用 provider/name 形式的模型 ID 为新线程选模型，--effort 设置思考强度。交互模式、-x 执行模式和 -ox orb 执行模式都支持。

用你自己的订阅

  • ChatGPT 订阅 — 关联后 OpenAI 模型计入 ChatGPT 订阅而非 Amp 积分。CLI 运行 amp config model-providers add-chatgpt-subscription（别名 amp add-chatgpt-sub）
  • Claude 订阅 — 在 Settings → Model Routing 中关联为 Claude Subscription，Claude 模型就走你的 Claude 套餐。Claude 模型通过 Claude Code 提供，首字延迟会更长
  • BYOK — 在 Model Routing 里加自己的 API Key

Orb 费用不由 ChatGPT / Claude 套餐覆盖，仍需用 Amp 积分或套餐额度支付；Painter 图像生成、网页搜索、读网页、语音也都消耗 Amp 积分。

🧩 模型与子代理

Amp 为不同工作使用不同模型：主代理负责你的任务，子代理承担其中聚焦的部分，更小的系统模型处理支撑性工作。

子代理

Amp 可以把聚焦的工作交给子代理，每个子代理有独立的上下文窗口：

  • Task — 端到端执行被委托的工作并汇报。它能编辑文件、运行终端命令，也内置只读技能：搜索工作区代码、研究其它仓库或依赖、审查改动、规划工作
  • Read Thread — 阅读并总结其它 Amp 线程

两个子代理都运行与启动它的线程相同的模型和思考强度。线程换模型后，已有子代理的后续任务也会用新模型。

💡 适合用子代理的场景：可拆成独立部分的多步骤任务、产生大量输出但事后不需要保留的操作、跨不同代码区域的并行工作，以及需要保持主线程上下文干净时。

子代理彼此隔离：它们不能互相通信，你无法直接指导它们，主代理只收到最终摘要。Task 子代理的上下文满了，Amp 会像压缩线程一样压缩它，让它继续接新任务。

系统模型

支撑性工作交给系统模型：分析图片、PDF、音频和视频；生成或编辑图片；给线程命名；压缩长对话的上下文。这样 Amp 能在需要深度推理处用前沿模型，在需要速度处用更快的专用模型。

Oracle、Librarian 与 Finder

这三者现在是 Task 子代理的一部分，可以用插件形式安装，从而让它们跑在你指定的模型上：

amp plugins add @amp/oracle
amp plugins add @amp/librarian
amp plugins add @amp/finder
  • Oracle — 审查代码、为困难决策提供建议，从不修改文件
  • Librarian — 把工作区外的仓库克隆到 /tmp，解释其代码与历史
  • Finder — 搜索你的工作区，返回相关文件和行范围

安装后从命令面板运行 plugins: reload。如果安装 Oracle，请一并安装另外两个，因为 Oracle 会把搜索交给 finder 和 librarian。

Claude Fable 与 BYOK

Anthropic 要求 Claude Fable 系列（含 Claude Fable 5.2）必须开启数据保留。若你用自己的 Anthropic API Key，请在拥有该 Key 的工作区中开启数据保留，再用该工作区的凭据发起 Fable 请求；零数据保留工作区的凭据无法访问 Fable。

💬 提示技巧

💡 第一条提示至关重要。用 Cmd/Ctrl+Enter 提交，提醒自己认真对待每一条提示。

基本原则

  • 明确表达 — 用「做 X」，而不是「你能做 X 吗？」
  • 一个线程一个任务 — 线程可以很长，但不该混入无关工作；别在改过 CSS 的线程里顺手让它写数据库迁移
  • 不要让模型猜 — 你知道的路径、命令、文件，直接写进提示
  • 只想规划就说明 — 「不要修改任何文件」
  • 用 AGENTS.md 指导 — 告诉 Amp 怎么跑测试和构建、如何避开常见错误，见 AGENTS.md
  • 告诉它如何自查 — 跑哪个命令或测试、打开哪个 URL、读哪些日志。反馈对代理和对我们一样有用

示例提示词

运行 <构建命令> 并修复所有错误

打开 <本地开发地址> 看这个 UI 组件，把它改得更简洁。经常截图检查你的工作

对我打开的这个文件跑 git blame，找出谁加了那个新标题

把这 5 个文件改成 Tailwind，每个文件用一个子代理

检查 git diff --staged，删掉别人加的调试语句

用示意图解释 AutoScroller 和 ViewUpdater 之间的关系

引用其它线程

可以在提示中引用线程 URL（如 https://ampcode.com/threads/T-…）或线程 ID（如 @T-…）。CLI 中输入 @@ 可搜索要提及的线程。Amp 会读取该线程并提取与当前任务相关的信息。

查找线程

可以让 Amp 按关键词、仓库、作者、日期或任务搜索你和工作区成员的线程。网页 feed 支持可收藏的 URL 过滤，例如 /feed?time=7d、/feed?q=label:bug，可用 id:、label:、project:、repo:、author:、visibility:、pr:、after:、before: 等过滤器。

附加图片与语音

  • CLI 中按 Ctrl+V 粘贴剪贴板图片（macOS 也是 Ctrl，不是 Cmd）。也可以把图片文件拖进终端
  • Windows 上 WezTerm 或 Alacritty 的粘贴比 Windows Terminal 更可靠
  • 听写默认快捷键：macOS Cmd+Shift+D，其它平台 Ctrl+Shift+D，可在键盘快捷键设置中修改

提及文件与技能

TUI 中输入 @ 搜索文件。网页与原生应用有意不支持文件提及——模型能自己找到相关文件，描述任务和想要的结果比逐个指文件更有效。要用某个技能，直接在提示里点名，例如「用 browser-testing 技能检查这个页面」。

消息排队与打断

  • 代理还在工作时发消息，默认是「引导」：当前步骤（命令或思考块）结束后就送达
  • 想等整轮结束后再发，网页按 ⌘+Enter（Windows/Linux 为 Ctrl+Enter），CLI 运行 prompt: queue message
  • 对已排队的消息按 Enter Enter 可提前引导
  • Esc Esc 强制停止代理并立即发送你的消息

🛠️ 工具与 Painter

Amp 会代你运行工具和 shell 命令来检查代码、跑测试、快速迭代。默认情况下，Amp 运行工具前不会请求批准。

⚠️ Amp 会作用于工作区里的内容。不受信任的仓库、MCP 服务器和外部输入都可能影响它的行为。如果你经常处理不受信任的来源，考虑写自定义策略插件，或使用隔离的开发环境。

内置工具

运行 amp tools list 查看当前版本的内置工具。

子代理

Amp 通过 Task 工具把聚焦工作交给子代理。你可以直接要求，例如「让子代理审查最后一次提交」「用子代理研究 Zod 如何实现可辨识联合」。详见 模型与子代理。

Painter（图像生成与编辑）

Amp 可以用 Painter 工具生成和编辑图片，底层是 GPT Image 2.5 Sunburst。

  • 可以在提示中用 @ 提及最多 3 张参考图，说明每张要保留什么、可以改什么
  • 每次调用生成一张图；Amp 可以在一次调用里要求多个变体，也可以多次调用
  • 需要叠在现有内容上的独立素材（logo、sprite），要求透明背景。Amp 会把工具的 background 选项设为 transparent，只在提示里写「透明」并不可靠
  • 完整构图（UI 样机、海报）以及自带设计背景的应用图标，应保持不透明背景
  • 做 UI 创意时，Amp 更倾向于构建可交互原型而不是出图

权限

Amp 默认不询问工具批准。需要控制工具使用时，写自定义插件；工作区管理员可以把它作为全局工作区插件分发。

☁️ Orbs

Orb 是 Amp 为线程创建的云端沙箱。每个 orb 线程都得到一个全新的隔离环境，里面有你的代码、插件、开发工具，以及创建它的线程的上下文。

为什么用 Orb

  • 合上笔记本也继续工作 — 代理在 orb 里跑，与你的电脑无关
  • 不占本机资源 — 同时开几个互不相干的任务，各自跑多久都行
  • 不用管机器 — 代理干完活，orb 自动休眠，休眠不收费，睡几周也没关系。再发提示时，会话、文件和服务都还在
  • 可以要求更完整的结果 — 它有一整台机器，能装依赖、跑应用、开浏览器做端到端验证

启动节奏

每个用户可以先连续启动 20 个计费 orb；之后每 5 分钟启动一个新 orb。后续启动会排队等待而不是失败，线程会显示预计等待时间。

查看改动与浏览文件

打开线程的 Changes 视图审查 diff；也可以在不克隆仓库的情况下浏览并打开 orb 里的任意文件。

使用终端

打开 Terminal 标签获得 orb 内的 shell。终端与代理使用同一文件系统和工作副本，任何一边的改动另一边立刻可见。它运行在共享的 tmux 会话中，Amp 能读取其输出并操作长时间运行的命令。

在任何设备上跟进

因为工作在 orb 而不是你的电脑上，你可以用任意设备查看。macOS、Windows、Linux、iOS、Android 的 Amp 应用显示与 ampcode.com 相同的线程，并在线程等待你回复时通知你。

上传文件到 Orb

  • 附加到线程 — 用输入框的附件按钮、拖入或粘贴。代理能看到附件，需要时下载进 orb
  • 通过 Files 面板上传 — 把文件拖到 Files 标签；拖到目录上就上传到该目录，拖到面板其它位置则上传到仓库根目录。也可以点击工具栏上传按钮，或右键目录选择 Upload Files…
  • 粘贴或拖进终端 — 粘贴图片或拖入文件，Amp 上传并把绝对路径插入光标处

通过 Files 面板或终端上传的文件每个最大 512 MB。

把改动同步到本机

amp sync <thread>

amp sync 会把 orb 线程的改动镜像到你的本地检出，同时代理仍在远端工作。需要在一个干净（没有未提交改动）的检出中运行。停止时会重置回原来的状态，所以运行期间不要本地编辑文件。

只想取一次结果，加 --apply：检出 orb 所在分支与最新提交、应用未提交的改动后退出，结果留在你的检出里。可用 --checkout 免确认切换分支，或 --skip-checkout 只应用改动。

从网页复制命令：线程的 More Actions 菜单里选 Orb → Copy Sync CLI Command。

从 CLI 启动 Orb

amp -ox "Investigate why the latest CI run on main failed"

需要不同算力时用 --orb-size：

amp -ox "Run the performance test matrix" --orb-size a1.large

从 TUI 启动 Orb

按 Ctrl+O 打开命令面板，选择 thread: new in orb。想先选项目，用 project: select；仓库还没有 Amp 项目时用 project: create。

⚙️ 为 Orb 准备仓库

项目里的第一个线程从普通 orb 开始。代理可以边干边装依赖，但每个新 orb 都要重复一遍。把两个脚本加进仓库即可避免：

  • .agents/setup — 安装依赖和工具。Amp 在准备新 orb 时运行一次，并把结果保存为后续线程使用的快照
  • .agents/resume — 每次唤醒后运行。用于刷新登录、重启服务等快速操作

最快的添加方式

项目里的第一个 orb 线程会在第一条消息上方显示 Enable Orb Caching 卡片，点击 Set Up 即可；也可以在项目页的 Set Up Orbs 提示中点击 Set Up with Amp。Amp 会发送一个请求，让代理按内置的 orb-setup 技能写好脚本、在 orb 中验证并提交。

你也可以自己说：

Prepare this repository so Amp can work on it in a fresh orb.
Create .agents/setup and .agents/resume, verify both by running
them in this orb, and commit them with the executable bit set.

新文件会出现在 Changes 面板里供你审查。之后 Amp 在准备项目快照时会运行 .agents/setup，该项目每个新 orb 都从准备好的状态开始。

项目级设置

  • Secrets & Env Vars — 存放 API Key 等配置，值会加密，个人值覆盖项目值
  • Orb — 设置默认机器规格，见下文
  • .amp/services.yaml — 提交到仓库，声明代理应启动并暴露的开发服务器

💰 Orb 规格与计费

按工作需要选择规格。小 orb 便宜，适合聚焦任务；大 orb 能跑更大的构建、更多服务和并行测试。所有规格都含 60 GB 磁盘。

规格 CPU 内存 标准价格
a1.tiny12 GB$0.08/小时
a1.small24 GB$0.17/小时
a1.medium48 GB$0.33/小时
a1.large816 GB$0.66/小时
a1.xxlarge1632 GB$1.32/小时
a1.3xlarge1644 GB$2.13/小时

a1.3xlarge 仅对 Gigawatt 订阅者和企业版工作区成员开放。

计费方式

Orb 按分钟计费，暂停中的 orb 不收费。Amp 在 orb 空闲时自动暂停，线程归档时立即暂停。在网页或原生应用中打开未归档的 orb 线程、打开 portal、发送新消息都会唤醒 orb，计费从启动并处理请求时恢复，再次暂停时停止。

什么时候暂停

以下两个条件都满足时暂停，取较晚者：

  • 代理已 5 分钟没有干活
  • 你已 20 分钟没有与 orb 交互

这是空闲超时，不是运行时长上限。代理有活干，orb 就一直运行，也只在这时计费。代理留下的后台服务（例如开发服务器）本身不会让 orb 保持唤醒，它会随 orb 一起暂停，唤醒后恢复。

怎么选规格

  • tiny — 调研、小脚本、带轻量检查的局部修改
  • small — 大多数单包项目和日常编码
  • medium — 中等规模构建、本地服务、测试套件
  • large — monorepo、多服务、CPU 密集型测试
  • xxlarge — 超大构建与并行负载

拿不准就从小的开始，下一个线程可以单独选更大的规格，不影响项目默认值。项目默认值是 a1.medium。

📁 项目

项目把一个代码库相关的一切放在一起：主仓库、在它上面工作的线程，以及该代码的每个 orb 共享的设置。项目还可以包含额外仓库，每个 orb 会把它们克隆到主仓库旁边。

项目支持 GitLab、Bitbucket 和其它 HTTPS Git 托管，不只 GitHub——用 orb 不需要把仓库搬到 GitHub。私有 GitLab 仓库请连接 GitLab；其它托管商的私有仓库需要先配置 Git 凭据。

也可以不用项目：选择 No Project 的线程会得到一个干净、无仓库的 orb，适合调研或一次性脚本。

创建项目

  1. 打开 Projects，点击 New Project
  2. 选择代码来源：
    • GitHub — 先在集成设置中连接 GitHub，再选仓库。私有仓库靠该连接克隆与推送；公开仓库无需连接
    • GitLab — 连接 GitLab 后选项目，或粘贴 HTTPS 克隆地址
    • Bitbucket / 其它 Git 托管 — 粘贴 HTTPS 克隆地址。公开仓库直接可用；私有仓库先建项目，再在 Secrets & Env Vars 里加凭据
    • Amp 托管 — 选 Start From Scratch，Amp 为你创建并托管一个空仓库，用 amp clone owner/project-name 克隆
  3. 选择归属：工作区项目对同事可见，私有项目只有你可见

用 CLI 创建

# 映射已有仓库
amp projects create acme/widgets
amp projects create https://git.example.com/acme/widgets

# Amp 托管的空仓库
amp projects create --amp-hosted --name widgets

# 把仅存在于本机的仓库推进新项目
cd myproject
amp projects create --push

主要设置

设置 说明
Git Repository Amp 克隆到每个 orb 的仓库。可为同一仓库的其它地址添加 Git Remote Aliases
Base Branch orb 检出的分支，也是 Ship 的目标分支。留空则使用仓库默认分支
Additional Repositories 每个 orb 会额外克隆到 ../repos/ 下的仓库，最多 20 个
Ship Behavior 决定 Ship 按钮让代理做什么
Default Orb 项目新线程默认在哪里运行，以及使用的规格
Pre-clone / Pre-setup Script 分别在克隆仓库前、.agents/setup 前运行，存放在仓库之外

只读 Git 凭据

Amp 托管的仓库可以创建只读凭据，让构建服务器、CI 或 GPU 机器无需以你的身份登录 Amp 即可克隆和拉取。在项目设置的 Read-only Git Credentials 中新建，选择 7/30/90/180 天或永不过期，然后复制 Authenticated Clone URL——凭据只显示一次。

权限

工作区成员都能在工作区项目中发起线程；修改工作区项目设置需要项目创建者或工作区管理员。私有项目只能由所有者使用和修改。

🧵 线程

线程是一次与代理的对话：你的提示、代理的回复、它调用的每个工具、它修改的文件。线程是 Amp 的工作单元：一个任务一个线程，可以在任何设备上继续，也可以交给同事。

每个线程都有一个 URL，例如 https://ampcode.com/threads/T-…。同一个线程可以在网页、CLI 以及 macOS / Windows / Linux / iOS / Android 应用中打开。代理在哪里运行，与你从哪里查看是两件事：线程可以跑在 orb、runner 或本地 CLI 会话中。

线程在哪里

侧边栏按项目列出最近的线程，置顶的排在最前。列表末尾的 Show Older 加载更早的线程；已休眠（Snoozed）的线程在 Filters 菜单里；72 小时内归档的线程在列表末尾的归档按钮后面。Activity 页（ampcode.com/feed）显示你能看到的所有线程，包括工作区成员分享的线程。

开始一个线程

在网页或应用里点击 New Thread，确认执行位置（New Orb / runner / 本地）与项目，然后描述你想要的结果。也可以从 CLI 用 amp、amp -x、amp -ox 发起。

线程内部

  • Changes — 列出已提交和未提交的改动。Ship 按项目的 Ship Behavior 提交并推送，Review 逐步走查 diff，Sync 把 orb 分支拉到本机
  • Portals — 显示 orb 中运行的 Web 服务
  • Files — 浏览 orb 或 runner 的文件系统，可拖放上传
  • Terminal — 在执行环境中打开 shell

Changes 面板会智能排序：Amp 读取 diff，把最能说明改动的文件放到前面，弱化生成代码等次要文件。diff 超过 500 个文件或你对线程只有只读权限时，退化为按字母排序。

在任何地方继续

  • 在手机或另一台电脑上打开 orb 线程继续提示
  • amp threads continue T-… 让 CLI 附着到线程
  • 从 More Actions 菜单的 Orb → Copy Sync CLI Command 复制带线程 ID 的 amp sync 命令

代理提交的 commit 会带 Amp-Thread-ID trailer，所以 git log 能从改动追溯到产生它的对话。

分享线程

点击标题栏的 Share，或命令面板里的 Share Thread…。在 General Access 中可以选择：

访问级别 谁能打开
Restricted 你、你添加的人与组，以及通过审计访问的工作区管理员
Your workspace 工作区全体成员
Anyone with the Link 拿到链接的任何互联网用户

打开 Multiplayer 后，有访问权的人都能参与：贡献者可以提示代理，查看者只能阅读。启用链接分享时无法使用 Multiplayer。在 CLI 中运行 set visibility、share with people，或 amp threads share T-… --visibility unlisted。

导出

在线程 URL 后加 .md 即可按 Markdown 阅读。More Actions 里的 Export 提供 Markdown，创建者还可导出完整 JSON。CLI 中对应 amp threads markdown 与 amp threads export。

整理线程

More Actions 菜单支持 Pin（置顶）、Color（颜色）、Labels（标签）、Rename（重命名）、Snooze（休眠并静音通知）、Archive（归档，URL 仍有效）、Delete（永久删除）和 Mark as Unread。

注意：归档一个线程不会归档它创建的子线程，它们会保持活跃并移到侧边栏顶层；想一起归档，用父线程上的 Archive N Threads。

一起工作

在输入框输入 @ 可以标记工作区成员，这会邀请他们并开启 Multiplayer。只有 orb 或共享 runner 上的非私有线程才能启用 Multiplayer，代理与 orb 费用计入线程所有者。

Artifacts

Artifact 是附在线程上的文档，你、同事和代理可以一起编辑，适合计划、报告、会议记录或跨线程汇集的发现。一个线程可以有多个 artifact，按文件夹分组，支持标题、列表、清单、表格、代码、图片和交互视图。每个 artifact 最大 2 MB。

📱 桌面与移动应用

Amp 在 Mac、iPhone、iPad、Android、Windows 和 Linux 上都有原生应用，提供与 ampcode.com 相同的线程、orb 和 Puck，并额外提供通知、听写和从其它应用分享内容的能力。

因为代理工作在 orb 里，你可以在办公桌前发起任务，然后在手机上跟进结果、回答问题或发送下一条提示。

登录

一台设备上最多可同时登录 5 个账号。打开用户菜单选择 Switch Account 添加或切换账号。

从链接打开线程

在手机和平板上，ampcode.com/threads/... 链接会在应用内打开。桌面端首次从外部收到线程链接时，页面会询问是否以后都在应用中打开；选择会按账号保存，可在 Settings > Appearance 中随时修改。

听写

可以口述消息而不必打字，首次使用会请求麦克风权限。想要与 Puck 双向语音对话，请使用 Call Puck。

🫧 Puck

Puck 是你的个人 Amp 助理，帮你管理 Amp 里的一切：启动代理、监控它们、给它们发消息、创建项目等等。

打开方式

  • ampcode.com：按 Ctrl+/ 打开或关闭，Puck 在侧边栏取代线程列表
  • TUI：Ctrl+O 打开命令面板选 puck: open，或按 Ctrl+X 再按 P
  • iOS / Android：打开侧边栏点 Puck
  • macOS：Puck 侧边栏菜单里的 Open in Separate Window 可开独立窗口

能做什么

  • 启动与指挥代理 — 「在 ampcode/amp 启动一个代理，查一下 CI 为什么挂了」
  • 查找与管理线程 — 找之前的对话、查看活跃线程、归档完成的工作
  • 发送保存的提示 — 内置 ship、update-base、refactor-commits、review，也可在 Prompts 页添加自己的
  • 操作项目 — 找项目、建项目、用正确的仓库和环境启动代理
  • 协调并行工作 — 把一个请求拆给多个代理，再汇总它们的报告
  • 使用技能 — Puck 会加载你的个人与工作区 skills（但它没有 orb，不能运行脚本，也不加载插件）
  • 使用已连接的服务 — 例如查看 GitHub checks 或在 Slack 中搜索上下文

语音通话

点击 Puck 输入框旁的 Call Puck，或按 Ctrl+Shift+/。在 Settings > Puck 的 Voice Call Instructions 中可写只对语音通话生效的指示，例如「我一直用中文回答」。

速度

Puck 默认 Standard 速度。想要更快，在 Settings > Puck 中选择 Fast 或 Plaid；越快越贵，菜单会显示价格。

在其它应用里使用 Puck

可以从 Claude、ChatGPT 等 MCP 客户端与同一个 Puck 对话。在 Settings > Puck 的 Puck in Other Apps 中：Claude 点 Add to Claude；其它 MCP 客户端添加远程 MCP 服务器 https://ampcode.com/mcp。该服务器提供三个工具：puck、new_puck_conversation 和 orbs。

🔌 集成

集成把 Amp 接到团队跟踪和审查工作的服务上。每个人在 Settings → Integrations & MCP 中连接自己的账号，Amp 就以该人的权限行动。工作区管理员在 Workspace Settings → Integrations & MCP 中安装共享应用、开关集成。

GitHub

让 orb 克隆私有仓库、推送分支、以你的身份开 PR。GitHub webhook 还能在 issue、PR 或 CI 运行变化时继续线程，或为每个新 issue / PR 启动一个新 orb。

GitLab

让 orb 在 gitlab.com 或自建实例上以你的身份克隆和推送、运行 glab，并在线程中跟进合并请求、issue 和 CI。

Google

让 Amp 读取并操作 Gmail、Google 日历、Docs、Sheets 和 Drive，每项服务可单独选择访问级别。

Linear

双向工作：在 Linear 里把 issue 指派给 Amp 或 @Amp，Amp 会在 orb 中处理并回复；在 Amp 里，orb 通过你的 Linear 连接读写 issue，也可以用订阅为每个新 issue 启动 orb。

Slack

在 Slack 里 @Amp 提问、开始工作或查看线程状态。默认情况下，除你自己的私信和由 @Amp 开启的线程外，Amp 在 Slack 中发帖、编辑、删除或加表情前都会先问你。

其它服务

任何有 MCP 服务器的服务（如 Sentry、Notion）都可以接入，见 MCP。

📋 AGENTS.md

Amp 从 AGENTS.md 文件中读取代码库结构、构建/测试命令和编码规范。

文件位置 典型内容
当前目录、父目录及子树的 AGENTS.md 架构、构建/测试命令、内部 API 概览、审查与发布步骤
$HOME/.config/amp/AGENTS.md
$HOME/.config/AGENTS.md		 个人偏好、设备特定命令，以及提交进仓库前本地试验的指导
/etc/ampcode/AGENTS.md
/Library/Application Support/ampcode/AGENTS.md
%ProgramData%\ampcode\AGENTS.md		 系统级或组织统一管理的指导

加载规则

  • 当前工作目录（或编辑器工作区根）以及父目录（直到 $HOME）里的 AGENTS.md 始终包含
  • 子树的 AGENTS.md 在代理读取该子树中的文件时包含
  • 系统级文件以及两个 $HOME/.config 下的文件若存在，始终包含
  • 如果目录里没有 AGENTS.md，但有 AGENT.md（少个 S）或 CLAUDE.md，则包含后者
  • 工作区管理员提供的 Global AGENTS.md 在个人与仓库指导之前包含，但不作用于子代理、Puck 和自定义代理

文件引用

在 AGENTS.md 中用 @ 引用其它文件作为上下文：

参见 @doc/style.md 和 @specs/**/*.md

提交时参考 @doc/git-commit-instructions.md
  • 相对路径相对于包含该引用的 agent 文件解析
  • @~/some/path 指向你的主目录；不支持绝对路径
  • 代码块中的 @ 引用会被忽略，避免误判
  • 支持 glob，例如 @doc/*.md、@.agent/**/*.md

条件生效（globs）

在被引用的文件里用 YAML front matter 的 globs，让规则只在处理特定文件时生效：

---
globs:
  - '**/*.ts'
  - '**/*.tsx'
---

遵循以下 TypeScript 规范：

- 永远不使用 `any` 类型
- ...

只有 Amp 读过匹配任一 glob 的文件时，该文件才会被包含；没有 globs 的文件每次被 @ 引用都会包含。glob 默认隐式加上 **/ 前缀，若以 ../ 或 ./ 开头则相对于被引用的文件。

忽略指导文件

设置环境变量 AMP_IGNORE_GUIDANCE_FILES（用 : 分隔的 glob 列表）可跳过匹配的指导文件，匹配的是绝对路径。例如在不改变 $HOME 的情况下跳过个人指导：

AMP_IGNORE_GUIDANCE_FILES="$HOME/.config/amp/AGENTS.md:$HOME/.config/AGENTS.md" amp -x "do the thing"

AMP_IGNORE_GUIDANCE_FILES='*' 会忽略所有指导文件，Amp 不再自动加载任何 AGENTS.md。

🧰 Skills

Skill 是包含特定任务说明和可选资源的目录。Amp 内置了一些技能，你也可以把技能放进项目、装到某台机器上，或发布给自己 / 工作区。

创建与安装

Amp 内置 building-skills 技能，可以直接让它帮你做：

为这个应用创建一个部署到预发环境的项目技能
为我的发布说明流程创建一个个人技能
从 github.com/example/engineering-skills 安装技能

项目技能保存在 .agents/skills/ 下，可随项目提交。个人技能在你使用 Amp 的所有地方可用。从 GitHub 仓库、Git URL 或本地路径安装：

amp skill add <source>

加 --global 只装到当前机器的 ~/.config/agents/skills/。

技能格式

每个技能是一个目录，里面有带 YAML frontmatter 的 SKILL.md：

---
name: my-skill
description: 这个技能做什么
---

# My Skill

给代理的详细说明……

Amp 会把所有技能的 name 和 description 列给模型，模型据此决定何时加载；调用时才加载 SKILL.md 的其余内容。技能目录里还可以放脚本、模板和参考文件，代理可按相对路径访问。

在技能里定义 MCP 服务器

技能可以在同级的 mcp.json 或 SKILL.md frontmatter 的 mcpServers 字段中定义 MCP 服务器（两者都有时，Amp 使用 mcpServers）。

{
  "chrome-devtools": {
    "command": "npx",
    "args": ["-y", "chrome-devtools-mcp@latest"],
    "includeTools": ["navigate_*", "take_screenshot", "click", "fill*"]
  }
}

技能定义的服务在技能加载前对模型隐藏，这样能保持工具列表干净。

查看与重载

amp skills list
amp skills list --json

也可以在 CLI 命令面板运行 skills: list。要让当前会话重新扫描，使用 reload_skills。

技能仓库

个人技能和使用 Amp 的所有地方共享，工作区技能对工作区全体成员可用，Amp 为每个范围维护独立的 Git 仓库。最简单的方式是直接让 Amp 在对话里处理，例如「为写发布说明创建一个个人技能」「把这个共享技能导入我的工作区技能」。Amp 会找到正确的仓库、准备改动、审查并提交，推送前会征求你同意。

直接编辑仓库时，每个技能放在顶层目录、SKILL.md 直接位于其中，目录名必须与 name 一致。托管仓库上限为 200 个技能；每个技能最多 200 个文件、单文件 10 MiB、单技能 25 MiB、仓库 25 MiB，且只接受文本文件。

🔗 MCP 服务器

通过 MCP（Model Context Protocol） 服务器添加工具，本地或远程均可。Amp 有两种配置方式：

  • 本地配置 — 存在 amp.mcpServers 中。URL 条目也属于本地配置，即使 URL 指向另一台机器
  • 远程定义 — 由 ampcode.com 存储，在 MCP 服务器设置或 amp mcp remote 中管理。由 Amp 的服务器发起连接

✅ 大多数场景下，推荐通过技能里的 mcp.json 打包 MCP 服务器，而不是加进用户设置：工具列表保持干净，只在需要时加载 MCP 工具。

添加服务器

amp mcp add context7 -- npx -y @upstash/context7-mcp
amp mcp add linear https://mcp.linear.app/sse

在配置文件中使用 amp.mcpServers，环境变量用 ${VAR_NAME}：

"amp.mcpServers": {
  "playwright": {
    "command": "npx",
    "args": ["-y", "@playwright/mcp@latest", "--headless"]
  },
  "linear": { "url": "https://mcp.linear.app/sse" },
  "sourcegraph": {
    "url": "${SRC_ENDPOINT}/.api/mcp/v1",
    "headers": { "Authorization": "token ${SRC_ACCESS_TOKEN}" }
  }
}

本地服务器用 command / args / env，远程服务器用 url / headers。

加载优先级（本地配置）

同名服务器出现在多处时，从高到低：

  1. CLI 参数（--mcp-config）
  2. 工作区配置（.amp/settings.json 中的 amp.mcpServers）
  3. 用户配置（~/.config/amp/settings.json）
  4. Skills

工作区服务器的信任

工作区设置中的 MCP 服务器在运行前需要明确批准，防止打开项目时自动执行不受信任的代码。等待批准时 amp mcp doctor 会显示 awaiting approval，用 amp mcp approve my-server 批准。

Orb 中的 MCP

本地（stdio）与远程 MCP 服务器都能在 orb 中工作。orb 在另一台机器上运行自己的 Amp 执行器，不读取你电脑上的设置文件，所以要配置在 orb 能看到的地方：

  • 通过技能打包 mcp.json 并提交到仓库（推荐）
  • 提交到仓库的工作区配置（.amp/settings.json），但需要批准
  • 在 MCP 服务器设置中添加远程定义，无需改动仓库

orb 中无法使用基于浏览器的 OAuth 流程。需要认证的远程服务器，请通过 headers 传 token（可用 secrets 设置里的环境变量）、发送 Amp ID token，或使用远程 MCP 定义（OAuth 通过 ampcode.com 完成）。

最佳实践

  • 把 MCP 服务器打包进技能，而不是全局添加
  • 选择暴露少量高质量工具、描述清晰的服务器
  • 禁用不用的 MCP 工具，或优先考虑直接使用 CLI 工具

🧩 插件

插件是给 Amp 添加工具、命令和事件驱动行为的 TypeScript / JavaScript 模块，可以是单个文件，也可以是带辅助文件的目录。插件会在你的环境中运行代码，只加载你信任的插件。

插件能做什么

  • 处理事件 — amp.on(...) 监听工具调用、工具结果和代理生命周期事件
  • 添加工具 — amp.registerTool(...)
  • 调用工具 — ctx.tools.call(name, input)
  • 打包技能 — await amp.registerSkill(...)
  • 添加命令 — amp.registerCommand(...)
  • 显示 UI — ctx.ui.notify / confirm / input / select
  • 用 AI 分类 — amp.ai.ask(...) 做线程内的是/否判断，amp.ai.decide(...) 做快速、带校准概率的类型化决策
  • 给线程打标签 — ctx.thread.addLabels(...)、ctx.thread.setLabels(...)

插件位置与优先级

  • 个人插件 — 在 Personal Settings 管理，使用 Amp 的所有地方都生效
  • 工作区插件 — 工作区管理员在 Workspace Settings 管理，对全体成员生效
  • 项目插件 — 放在项目根目录的 .amp/plugins/，在该项目中运行 Amp 时生效
  • 系统插件 — $XDG_CONFIG_HOME/amp/plugins/，未设置时为 ~/.config/amp/plugins/（Windows 为 %USERPROFILE%\.config\amp\plugins\）

安装单个文件插件

amp plugins add <url>

加 --target workspace 则装进当前项目的 .amp/plugins/。

编写插件

单文件插件是插件目录下直接的 .ts / .js；目录插件用 <plugin-name>/index.ts 或 index.js（两者都在时用 index.ts）。入口文件默认导出一个函数，Amp 传入 PluginAPI 对象。

import type { PluginAPI } from '@ampcode/plugin'

export default function (amp: PluginAPI) {
  amp.registerTool({
    name: 'project_status',
    description: 'Show the current git status for this repository.',
    inputSchema: { type: 'object', properties: {}, required: [] },
    async execute() {
      const result = await amp.$`git status --short`
      return result.stdout || 'No changes.'
    },
  })
}

重载

修改插件后让 Amp 重载，或在命令面板（Ctrl+O）运行 plugins: reload / plugins: list。在 shell 中运行 amp plugins list 可查看已加载插件及其来源、事件、命令和工具。

自定义代理模式

用 amp.createAgent(...) 和 amp.registerAgentMode(...) 添加自定义代理模式，它会出现在模型选择器的 Your Agents 分组中。模式的 model 必填；每个 Task 子代理都会使用同一个模型与思考强度。

⚠️ 旧写法用 extends 继承内置模式，现在 extends 与 model 同时出现会被忽略；只写 extends 而没有 model 会报错。自定义模式的 key 与 label 必须唯一、非空、不超过 24 个字符，且不能与内置模式冲突。

💻 CLI 入门

Amp CLI 在你的终端中运行，可以让 Amp 代理跑在本机、orb 或已连接的 runner 上。支持 macOS、Linux 和 WSL（Windows）。Windows 上推荐使用 WezTerm 或 Alacritty 以获得完整的剪贴板支持。

安装与启动

curl -fsSL https://ampcode.com/install.sh | bash

amp                      # 交互模式
echo "提交我所有的改动" | amp   # 管道输入
amp --help

管理 CLI 账号

  • amp login — 添加账号并设为当前服务器上的活跃账号
  • amp account list — 查看已保存账号
  • amp account switch <email-or-user-id> — 切换后续命令使用的账号；已在运行的进程不受影响
  • amp logout / amp logout --all — 移除当前 / 全部已保存账号

Shell 补全

source <(amp completions bash)   # Bash 4+，需先加载 bash-completion
source <(amp completions zsh)    # Zsh，放在 compinit 之后
amp completions fish | source    # Fish
amp completions pwsh | Out-String | Invoke-Expression   # PowerShell 7

选择线程在哪里运行

amp --executor local
amp --executor orb
amp --executor runner:grandmas-garage-server

orb 线程使用与当前目录 Git remote 匹配的 Amp 项目；没有匹配时 Amp 会警告并使用无项目的 orb。

更新与版本

amp update
amp version

连接编辑器

Amp 可连接 VS Code、Cursor、Windsurf、Zed 和 Neovim。打开编辑器，运行 amp，然后按 Ctrl+O 打开命令面板选择 ide connect。集成让 Amp 看到当前打开的文件与选区，并通过 IDE 编辑文件（支持完整撤销）。Neovim 还需要安装 amp.nvim 插件。

🤖 执行模式

用 -x 或 --execute 启动执行模式：把消息发给代理，等它结束本轮，打印最终消息后退出。用 -ox 则在 Amp 服务器的 orb 中运行同样的提示。

amp -x "这个文件夹里哪些是 markdown 文件？只打印文件名。"
echo "这里用的是什么包管理器？" | amp -x

# 同时看管道输入和提示
cat ~/.vimrc | amp -x "用的是哪个配色方案？"

重定向 stdout 时会自动进入执行模式：

echo "what is 2+2?" | amp > response.txt

不改设置临时指定 MCP

amp --mcp-config '{"everything": {"command": "npx", "args": ["-y", "@modelcontextprotocol/server-everything"]}}' -x "What tools are available to you?"

计时

amp -x "summarize this repo" --timings

计时报告输出到 stderr，响应仍在 stdout，因此也能配合 --stream-json 和输出重定向使用。

启动 Orb 与 Runner 线程

amp -ox "Investigate why the latest CI run on main failed"

amp -x "Run the tests and fix any failures" --executor runner:mac-mini

用 --runner-dir 指定 runner 上的其它目录，用 --attach <path> 上传文件并把附件 URL 加入消息（可重复）。

非交互环境

脚本和 CI/CD 中，把访问令牌放进环境变量：

export AMP_API_KEY=your-access-token-here

令牌以 sgamp_ 开头，在 Settings 中创建。CLI 会拒绝 amp login 保存的短期会话令牌，因为它一小时内过期且无法从环境变量刷新。要以工作区身份（而非个人身份）运行流水线，请使用服务账号的 API Key。

写提示

  • Enter 提交。代理还在工作时，Enter 默认是引导（当前步骤后送达）；想排队，运行 prompt: queue message
  • 终端支持 modified Enter 时（Ghostty、WezTerm、Kitty、iTerm2、开启 extended-keys 的 tmux），Shift+Enter 换行；任何终端都可用 Ctrl+J，或输入 \ 后回车
  • tmux 用户需启用 set -s extended-keys on

自定义键位

{
  "amp.keymap": {
    "mode.toggle": ["ctrl+s", "ctrl+j"],
    "thread.copyURL": "<leader> u",
    "thread.interrupt": ["esc esc", "ctrl+l"]
  }
}

用空格分隔表示组合键（如 ctrl+c ctrl+e）。配置某个命令会替换其默认键；用数组可保留旧快捷键并新增；设为 null 可解绑。注意：用户设置里的 keymap 会覆盖工作区设置里的同名项。

托管设置

工作区管理员可以在 Workspace Settings 的 Managed Settings 页写一份 JSON 文档（键与 managed-settings.json 相同），也可以把本地 managed-settings.json 分发到每台机器：

  • macOS：/Library/Application Support/ampcode/managed-settings.json
  • Linux：/etc/ampcode/managed-settings.json
  • Windows：%ProgramData%\ampcode\managed-settings.json

运行 settings: show managed 可查看工作区托管了哪些键。

💰 定价

Amp 没有按量付费之外的强制门槛：可以选月度档位拿到更高性价比，也可以按标准费率随用随付。关联 ChatGPT / Claude 订阅还能把对应模型的用量计入订阅。

🎁 Hobby（免费）

包含全部产品功能；Amp 托管的 orb 按量付费；自托管 orb 与 runners 免费且不限量；可用任何来源的 token、自带 Key（BYOK）

💳 Individual（$20/月起）

Megawatt 档含 45,000 分钟 Amp 托管 orb 时长；Gigawatt 更高；自托管 orb 与 runners 仍免费；不限公开/私有仓库；可用自己的域名托管 portals

👥 Teams（不额外收费）

成员可分属不同档位；团队线程分享、Multiplayer 与权限；共享 portals、插件与技能；用户管理与分析；共享账单与合并积分；SAML/OIDC SSO

🏢 Enterprise（定制）

含 Individual 与 Teams 全部能力，另有 SCIM、支出限额与报表、审计日志、IP 白名单、区域端点、更高配额与优先支持

登录后还可以选择 Megawatt 50（$50/月），包含 2.5 倍于 Megawatt 的代理与 orb 用量。

用量如何计费

  • 档位内含的代理用量用完后，可以加购积分继续工作。Amp 按线程中实际的模型与工具用量扣费；对个人和非企业工作区不加价（即直接透传供应商 API 价格）
  • 付费积分无需订阅或承诺。网页搜索等非模型工具也消耗积分
  • 示例：某线程用了 $2 的 Anthropic API 和 $0.50 的 OpenAI API，Amp 从积分中扣 $2.50
  • Orb 使用单独的额度，按分钟计费，暂停不收费
  • 积分可在用户设置、工作区设置中购买和查看，或运行 amp usage。购买的积分自购买起 12 个月后过期；工作区成员共享工作区积分

💡 想看某个线程的详细花费，点击线程页右侧的 $ 价格；也可以直接问 Amp 解释你的用量。
